## ⛔ 行为层红线（和内容层同等重要）

| | |
|---|---|
| `库/违规词红线.md` | 管**内容写什么** —— 绝对化用语、承诺词、引流 |
| `库/平台风控红线.md` | 管**账号怎么操作** —— 互关、建群、同步互动 |

**后者翻车更彻底：一次整组封禁。**

绝对不能做：自己的号互相关注 / 拉进同一个群 / 互相点赞收藏 /
同一 IP 短时间登录多个号 / 多个号同时段发布。

「转发」不能形成主页内容（只能分享到站外/私信/群），
所以多号之间无法通过转发互相供给 —— 每个号想有内容只能自己发。

## 发布流水线的六道关

```
[1/6]   自检        载荷逻辑单测（本地 <1s）
[2/6]   飞行前体检  登录 + 平台风控              → 退出码 2
[3/6]   轮换校验    草稿账号 == 本轮主发号        → 退出码 6
[4/6]   账号健康度  危险期 / 周配额 / 间隔        → 退出码 4
[5/6]   红线扫描    绝对化 / 承诺 / 引流          → 退出码 3
[5.5/6] 本地化检查  跨区域 / 全国性表述 / 地域词  → 退出码 7
[6/6]   发布        文字配图自动生图
```

**每一道都对应一次真实踩过的坑。**

| 关卡 | 拦的是什么 | 不加会怎样 |
|---|---|---|
| 自检 | 载荷逻辑回归 | Markdown 标记被原样印在图上 |
| 体检 | 被风控还硬发 | 冷却越来越长 |
| 轮换 | 绕过轮换想发就发 | 发布频率回到"每号各发"，风险翻倍 |
| 健康度 | 在危险期发内容 | 新号直接被打 |
| 红线 | 绝对化用语、引流 | 限流、删帖 |
| **本地化** | **跨区域、非本地表述** | **触达不到能办理的人，或超出授权** |

## 两个扫描器

内容层有两套独立的检查，都要过：

| 扫描器 | 查什么 | 文件 |
|---|---|---|
| `scan_redline.py` | **合规**：绝对化用语、承诺词、引流话术 | `库/违规词红线.md` |
| `scan_local.py` | **本地化**：跨区域词、全国性表述、标题地域词、正文本地场景 | `库/本地化策略.md` |

## 卡点与依赖

```
健康度 ←── 注册日（人工填）      ← 必须填，推定值会导致阶段判断错
轮换   ←── 已登录的运营号         ← 号没登录就进不了轮换池
迭代   ←── 笔记数据（sync_notes） ← 没有数据，迭代回路是空的
互动   ←── 笔记 ID（sync_notes）  ← 没有 ID，评论读不到
排期   ←── 草稿的账号字段         ← 没写账号排不了期
```

`sync_notes.py` 同时供给迭代和互动 —— **它是最上游的缺口**。

## 互动（获客）怎么运作

```
定时采集评论
    ↓  get_feed_detail(load_comments=True)  —— 不爬创作者后台，用固定接口
自动分级
    ↓  高 = 有明确问题或意向（潜在客户）
    ↓  中 = 真实互动，没有明确问题
    ↓  低 = 寒暄、表情
只对高价值提醒
    ↓  桌面通知 + 提示音 + 页面横幅（横幅不会自动消失）
你回复
    ↓  python engage.py --reply <ID> "内容"
```

### 分级为什么重要

一堆「学到了」里混着一条「请问移机要收费吗」——
**后者是客户，前者不是。** 不分开，回复优先级就靠感觉。

**分级尺度偏向误报**：中文里「…吗」「…呢」结尾基本是问句，
所以「我学到了吗」这种也会判成高。这是有意的 ——
**漏掉一个真客户的代价，远大于多看一条无关评论。**

### 提醒的三个通道

| 通道 | 条件 | 特点 |
|---|---|---|
| 桌面通知 | 需授权（点顶部「开启提醒」） | 关着页面也能看到 |
| 提示音 | 提醒开着时 | Web Audio 合成，不引音频文件 |
| 页面横幅 | 总是有效 | **不自动消失，必须手动关** |

桌面通知和声音只在**新出现**的高价值评论时响，响过的记住不重复。
首次加载不响（否则每次刷新都提示一遍历史评论）。

### 采集为什么用 get_feed_detail

爬创作者后台评论页要猜 DOM 结构，改版就废。
`get_feed_detail(load_comments=True)` 的返回结构是固定的：

```python
{"id", "content", "user_id", "nickname", "like_count", "create_time"}
```

**前置条件**：需要笔记的 `feed_id` + `xsec_token`，从 `数据/笔记数据.json` 读
（由 `sync_notes.py` 采集）。

### ⛔ 互动里唯一不能碰的

**不要让自己的号互相点赞、收藏、评论、关注。**

这不是"效果不好"，是**整组被封**的路径。详见 `库/平台风控红线.md`。
互动只能对**真实用户**做，且低频。

## 贴吧获客（号卡主战场）

小红书负责内容和品牌，**贴吧负责找人**。两套独立的登录态和风控 ——
小红书制动期不影响贴吧。

```
8 个吧（实际 6 个，广电吧未建立）
    ↓  aiotieba 调 App 私有接口，BDUSS 登录（只读，用不到 STOKEN）
拉帖列表（按回复时间倒序）
    ↓  新鲜度过滤（老帖不是线索）+ 水楼过滤（练级楼动辄几千回复）
增量拉楼：只拉比上次新的楼层（get_posts 没有「某 pid 之后」接口，
    ↓     所以按 DESC 从最新往回走，碰到旧楼就停）
意向分类（意向.py）
    ↓  6 类话题 + **求助语气**（在问/在求才算，光提业务名不算）
过滤三类噪声
    ↓  同行（短链/返佣/号卡平台）· 水楼 · 卖家（闲置/转让）
提醒（notify.py：控制台横幅 + 可点链接 + 系统通知）
    ↓
人手动去贴吧回复（工具**绝不**代发）
```

### 两个被实测逼出来的关键设计

| 设计 | 为什么 |
|---|---|
| **判「是不是意向」靠求助语气，不靠话题词** | 在「四川联通吧」里每帖都提「联通」，只看话题词单吧命中 **300+ 条** |
| **过滤卖卡帖和水楼** | 「绵阳宽带安装」是广告不是客户；「本吧练级大楼」2497 回复能被一句「求」命中 |

### ⛔ 贴吧三条硬纪律

1. **工具只读不写** —— 不回复、不发帖、不顶贴。回复由人在浏览器手动做。
2. **回复里绝不放微信/手机号** —— 《贴吧协议》2.5 以「带联系方式」为广告要件。
3. **绝不用黑话规避审核**（绿泡泡/加V）—— 平台 AI 已能识别，写了没用还多一条记录。

详见 `AGENTS.md` 的「贴吧获客」一节。

## 每日互动配额（保守值）

运营号要长期养，互动的目的不是刷量，是**让账号看起来像个正常用户**。

| 动作 | 每天上限 | 说明 |
|---|---|---|
| 回复自己笔记的评论 | 不限 | 最安全，也最有价值 |
| 点赞真实相关内容 | ≤ 10 | 只点相关领域 |
| 收藏 | ≤ 5 | |
| 评论别人内容 | ≤ 3 | 必须有价值，不能是「学习了」 |
| 关注 | ≤ 3 | 只关注真实有兴趣的用户 |
| **取关** | **不要做** | 大比例取关是刷量的明确信号 |

**超过配额不如不做。** 低频养号，高频找死。

## 日常操作顺序

```powershell
# 每 3-5 天：采集热点（会自动跳过缓存期内的词）
python trends.py                 # 采集 + 分析 + 出方案
python trends.py --analyze       # 只看分析（不碰平台）
python trends.py --plan          # 只出方案（不碰平台）

# 每天
python rotation.py                            # 本轮谁发
python auto_publish.py "草稿\xxx.md" --dry-run  # 先演练
python auto_publish.py "草稿\xxx.md"            # 真发
python rotation.py --next                     # 推进轮换

# 每 1-2 天
python sync_notes.py      # 同步数据（1 次请求）
python engage.py          # 同步评论
python engage.py --list   # 看待回复

# 每周
（用 xhs-iterate 技能复盘）
python health.py          # 检查各号状态
```

## 热点采集的节流设计

`trends.py` 每次搜索 = 一次平台请求，所以有三层节流：

```
每次最多采 4 个关键词      MAX_KEYWORDS
词与词之间隔 22 秒          INTERVAL
同一个词 3 天内不重采        CACHE_DAYS
```

**不要去掉这三层。** 一次性把 6 个词全搜完，等于自己制造一次高频访问。

## 数据真实性的纪律

**绝不往 `数据/` 里写编造数据。**

2026-10-12 发生过一次：为了让「内容方案」看着丰富，我在种子数据里
补了 6 条不存在的笔记。清理后的真实结果是**一个关键词覆盖不到 5 个人设**。

编造数据制造的「功能有效」假象，比功能没建更糟 —— 它会让你按错误的
信号做选题决策。清理工具留在 `clean_fake.py`。
```

## 每个功能的退出码约定

脚本的退出码就是给流水线用的信号，不要改：

| 退出码 | 含义 |
|---|---|
| 0 | 通过 / 可用 |
| 1 | 输入问题（缺字段、找不到账号） |
| 2 | 被风控 / 冷却中 |
| 3 | 内容违规 |
| 4 | 账号健康度不允许 |
| 5 | 发布失败（平台侧） |
| 6 | 轮换不匹配 |
| 7 | 不是绵阳本地口径 |

## 维护约定

**加新功能时**：
1. 在 `auto_publish.py` 里做成一个 `gate_*()` 函数
2. 退出码按上表
3. 更新本文件
4. 如果是新的判断逻辑，加一个 `test_*.py`

**不要**：把判断逻辑散在各个脚本里各写一套。
健康度的判断只在 `health.py`，工作台直接调它 —— 一处改，处处对。
